# 前端操作说明书（九厂一期工艺参数监控大屏）

> 这本手册写给**第一次接触这套系统的人**：系统是干嘛的、每个页面**每一个按钮/开关/输入框**怎么用、点了之后会发生什么、微信/短信里会收到什么。安装部署见 [windows-deploy.md](windows-deploy.md)，系统结构见 [system-guide.md](system-guide.md)。

## 0. 三分钟看懂这套系统

**这套系统是干嘛的？**

它像给 4 台水处理设备请了一个 **7×24 小时不休息的值班员**：每 13 分钟读一次每台设备的 6 个水质指标，数值一旦越界、或设备失联，就自动记一条告警，并按名单把通知发到值班人的**手机微信（或短信）**上。大屏就是那个值班员的「监控台」——电脑上打开浏览器就能看。

**几个必须知道的名词（大白话）**

| 名词 | 大白话解释 |
|---|---|
| 设备 | 被监控的 4 台水质传感器，每台有个**编号**当身份证，形如 `Di-Jiu-Shui-Chang-1` |
| 指标（参数） | 每台设备上报的 6 个水质数值：沉降速度、沉降比、机加池出水浊度、PH、温度、反应池污泥浓度 |
| 阈值 | 你给每个指标划的「安全线」——一个下限、一个上限。数值跑到线外 = 异常 |
| 越限 | 数值超上限或低于下限（压线不算，要**严格**超出） |
| 离线 | 设备超过 13 分钟没上报数据（可能断电、断网、坏了） |
| 告警 | 越限或离线时系统记下的一条记录，同时发通知 |
| 接收人 | 出事时通知谁——存的是**手机号**，可额外配**微信** |
| 检测器 | 后端那个「巡逻员」程序，每 10 秒检查一次数据，负责判定告警和发通知 |

> **一个会混淆的点提前说清**：大屏界面上设备一律显示**编号**（`Di-Jiu-Shui-Chang-1`），而**微信/短信通知里显示中文名**（`九厂一期-1#`）——它们是同一台设备，对照表见 §9。

## 1. 顶栏（每个页面都有）

顶栏最上面一行，三个页面通用。**里面有一个按钮、三个菜单、几项状态显示**：

| 控件 | 是什么 | 怎么用 / 点下去会怎样 |
|---|---|---|
| **菜单「实时监控」** | 页面入口 | 点一下跳到监控大屏 |
| **菜单「告警记录」** | 页面入口 | 点一下跳到告警历史列表 |
| **菜单「阈值配置」** | 页面入口 | 点一下跳到阈值/接收人配置页 |
| **🔔 铃铛按钮** | 未读告警角标 | 右上角。**点一下 = 把所有告警标记已读 + 跳到告警记录页**；按钮上红色的数字 = 未读条数，超过 99 显示 `99+`，没有未读时数字隐藏 |
| ● 检测器运行中 / 已停止 | 状态显示 | 后端检测器心跳：绿点=在岗，红点=已停，每 60 秒自动刷新。**没有这一项 = 前端跑在模拟模式**（不连后端） |
| 在线 n · 离线 n · 异常 n | 状态显示 | 四台设备实时统计，随数据自动刷新 |
| 右上时钟 | 时间显示 | 当前时间，每秒走 |

## 2. 实时监控页

**这页干嘛的：** 一屏看全 4 台设备的实时状态，谁出问题一眼就知道。数据约 2 秒自动刷新，无需手动操作。

### 2.1 设备卡片（可点击）

主界面是 2×2 四张卡片，每张一台设备。卡片从上到下：

- **标题**：设备编号（`Di-Jiu-Shui-Chang-1`）；
- **右上角状态角标**：在线（绿）/ 离线（灰）/ 异常（红）；
- **中部 6 个指标当前值**：沉降速度、沉降比、机加池出水浊度、PH、温度、反应池污泥浓度。**越限的那一项变红色加粗**；
- **底部最近上报时间**：`时间(n 秒前)` 倒计时，超 13 分钟无新数据判离线。

**卡片 = 一个按钮**：**鼠标点整张卡片** → 右侧滑出这台设备的详情抽屉（见 2.2）。卡片悬停时边框会变蓝，提示「可点」。

**状态角标怎么判定**（只做展示，不参与真正报警）：

| 状态 | 规则 |
|---|---|
| 离线 | 超过 13 分钟无新上报 |
| 异常 | 任一「参与监控」的指标**严格**超出上下限（压线不算） |
| 在线 | 其他情况 |

> 角标只是展示提示（关浏览器就没了）；真正报警判定和发通知由后端检测器做。

### 2.2 设备详情抽屉

点卡片打开，右侧滑出。抽屉里**有一个可关闭区域、6 个可点的指标方块**：

| 控件 | 怎么用 / 点下去会怎样 |
|---|---|
| **右上角 ×** | 关闭抽屉（点抽屉外空白处也能关） |
| **设备照片** | 展示，不可点 |
| **档案信息表** | 设备编号、状态、负责人、通信方式、最近上报时间（纯展示） |
| **6 个指标值方块** | **点任一方块 → 底部趋势图切换成该指标的历史曲线**；被选中的方块有蓝框高亮。刚打开抽屉时默认选中「沉降比」 |
| **趋势曲线图** | 展示当前选中指标的历史变化，随数据刷新 |

## 3. 告警记录页

**这页干嘛的：** 看历史告警——谁、什么时候、哪个指标出了问题。告警由后端检测器生成（浏览器关着也产生），本页**每 30 秒自动拉取**。新告警到达时右上弹通知（严重=红、警告=黄），铃铛 +1。

### 3.1 按钮与控件清单

这页**有 2 个筛选下拉、1 个清空按钮**：

| 控件 | 怎么用 / 点下去会怎样 |
|---|---|
| **下拉「全部设备」** | 筛选：点开选某台设备，只看它的告警。**点右侧 × 清除筛选**，恢复全部设备 |
| **下拉「全部类型」** | 筛选：超上限 / 超下限 / 离线。**点右侧 × 清除**。两个下拉可同时生效（组合过滤） |
| **按钮「清空记录」**（右上红钮） | **点一下 → 弹确认框「确定清空全部告警记录?」→ 点确定才真删**，删光全部告警并提示「已清空」；点取消则不动 |

> 告警记录最多留 500 条，满了自动丢最旧的，所以平时不用管，想清爽可定期清空。

### 3.2 列表每一列什么意思

| 列 | 含义 |
|---|---|
| 时间 | 告警发生时间（新的在最前） |
| 设备 | 哪台设备（编号） |
| 参数 | 哪个指标；离线告警显示「整机」 |
| 类型 | 超上限（黄标签）/ 超下限（黄）/ 离线（红） |
| 当前值 | 触发时的数值（离线为 `--`） |
| 阈值 | 它越过的那条线（离线为 `--`） |
| 级别 | 警告（指标越限）/ 严重（离线） |
| 短信 | 已发送 / 发送中 / 失败，及接收人数；**名单为空显示「失败 · 无接收人」** |

## 4. 阈值配置页

**这页干嘛的：** 定「安全线」（阈值）和「通知谁」（接收人）——日常最常改的地方。分上下两块：**4.1 告警阈值、4.2 接收人**。

### 4.1 告警阈值区

| 控件 | 怎么用 / 点下去会怎样 |
|---|---|
| **标签页 ×4** | 顶部 `Di-Jiu-Shui-Chang-1..4` 四个标签，**点标签切换设备**，每页 6 个指标 |
| **下限输入框** | 数字框，直接改。小数位按指标类型固定（如沉降比 1 位、沉降速度 2 位），步进 1 |
| **上限输入框** | 数字框，同下限 |
| **参与监控开关** | 开关打开=这个指标越限要报警；**关掉=这个指标出问题不报警**（不参与判定） |
| **按钮「保存」**（右上蓝色） | **点一下先校验**：某行下限 ≥ 上限 → 红字报错「XX设备 XX指标：下限必须小于上限」，不保存；全部合法 → 保存成功并提示「已保存，后端检测器约 10 秒内采纳」 |

> **保存后的生效节奏**：界面状态角标**立即**按新线变；后端判定约 **10 秒内**采纳。各指标默认安全线见 §9。

### 4.2 接收人区（通知名单）

**这块管「出事通知谁」**。表格每行一个人，列：姓名、手机号、订阅设备、微信 openid、操作。

| 控件 | 怎么用 / 点下去会怎样 |
|---|---|
| **按钮「添加接收人」** | 打开「添加接收人」弹窗（见 4.3） |
| **勾选框「订阅设备」×4** | 每行 4 个设备编号勾选框。**勾选/取消立即保存**（不用点别的按钮），约 10 秒被后端采纳。一个都不勾时该行显示灰字「未订阅任何设备，将不会收到短信」，并弹提示「已更新：未订阅任何设备」 |
| **「微信 openid」列** | 纯展示：配了显示 openid 串（鼠标悬停看完整），没配显示灰字「未配置」 |
| **按钮「编辑」**（每行） | 打开「编辑接收人」弹窗，回填该行全部字段（见 4.3） |
| **按钮「删除」**（每行，红色） | **点一下 → 弹确认框「确定删除该接收人?」→ 确定才删**，移出名单 |

> **上线前务必给每台设备配好订阅人**：某设备没人订阅时，它的告警通知状态记「失败」、接收人为空。微信渠道开关在后端 `.env`（`SMS_PROVIDER=wechat_sandbox`），前端不用管。

### 4.3 接收人弹窗（添加 / 编辑共用一个弹窗）

点「添加接收人」或「编辑」弹出。**里面 4 个输入框、1 个二维码、1 个获取按钮、底部 2 个按钮**：

| 控件 | 怎么用 / 点下去会怎样 |
|---|---|
| **姓名输入框** | 必填。留空点确定会提示「请输入姓名」 |
| **手机号输入框** | 必填，**必须 1 开头 11 位数字**，错了点确定提示「手机号须为 1 开头的 11 位数字」 |
| **订阅设备勾选框组** | 勾选该人要订阅的设备（一个不勾 = 收不到） |
| **微信 openid 输入框** | 可选。不填 = 微信渠道发不了（短信照常）；清空保存 = 取消该人的微信通知。可手动粘贴 openid |
| **测试号二维码** | 展示，用手机微信扫它关注测试号 |
| **按钮「获取最新关注」** | 见下方详细说明 |
| **按钮「取消」** | 关闭弹窗，**丢弃这次没保存的修改** |
| **按钮「确定」** | 先校验姓名/手机号，通过后保存（添加 or 更新）并提示成功；**编辑时清空 openid 提交 = 取消微信渠道** |

**「获取最新关注」按钮的完整逻辑**：

1. 先让要配的人**用手机微信扫二维码关注测试号**；
2. 点「获取最新关注」，按钮转圈（加载中，连点无效），系统去微信拉「最新关注、且还没绑给任何接收人」的那个 openid；
3. 按结果分支：

| 情况 | 发生什么 |
|---|---|
| 拉到 openid，输入框**为空** | 自动填入输入框，下方出绿字「已填入：x 分钟前关注，请确认时间对得上再提交」 |
| 拉到 openid，输入框**已有值** | **不覆盖**，提示「输入框已有 openid，未覆盖；要换人请先清空再获取」 |
| 没人新扫码 | 提示「暂无新关注——扫码关注测试号后再点获取」 |
| 渠道没配 / 微信接口异常 | 提示「获取失败：微信渠道未配置或接口异常，请稍后再试」 |

4. **核对绿字时间对得上再点「确定」**——确认拉到的真是刚扫码这个人（不是早前关注的别人）。已绑定过接收人的关注者不会被拉到。

## 5. 微信会收到什么

告警触发后，订阅了该设备且配了 openid 的人，手机会收到一条**公众号模板消息**（像公众号推送一样，有提醒）。消息固定四行「标签 + 值」：

| 行标签 | 填什么 |
|---|---|
| 设备 | 设备中文名（如 `九厂一期-1#`） |
| 内容 | 「指标名 数值+单位」；离线时为「设备离线」 |
| 详情 | 「超上限 / 低于下限 + 阈值+单位」；离线时为「超过 N 分钟」 |
| 时间 | 告警时间，`月-日 时:分:秒` |

**收到后的样子（真实样例）**

① 指标越限（例：沉降比飙到 36.2，超了上限 35）：

```
设备：九厂一期-1#
内容：沉降比 36.2%
详情：超上限 35%
时间：10-20 21:15:48
```

② 设备离线（例：九厂一期-1# 失联）：

```
设备：九厂一期-1#
内容：设备离线
详情：超过13分钟
时间：10-20 21:15:48
```

> 每个值最多显示 16 个字，超长截断加「…」；文字统一深蓝色。**消息里的「九厂一期-1#」就是大屏上的「Di-Jiu-Shui-Chang-1」**，同一台设备（对照 §9）。

## 6. 常用操作场景

**场景 A —— 演示「指标越限报警」**：阈值配置页选一台设备 → 把某指标上限调低到当前值以下（如沉降比上限改 5）→ 点「保存」→ 等约 10 秒，告警记录页出现「超上限 / 警告」，页面弹通知，短信列显示「已发送」（前提：该设备已配订阅人；后端 `SMS_PROVIDER=dryrun` 时只记日志不真发）→ 演示完把阈值改回。

**场景 B —— 演示「离线报警」**：让某台设备停止上报（或停掉模拟发送端）→ 13 分钟后产生「离线 / 严重」告警；设备恢复上报**不会**产生「恢复告警」。

**场景 C —— 日常巡检**：打开大屏 → 看顶栏「检测器运行中」是否绿、四台角标有无离线/异常 → 有未读铃铛点开处理 → 必要时用筛选查历史告警。

**场景 D —— 给值班人员配微信通知**：阈值配置页 → 添加接收人 → 该人扫弹窗二维码关注测试号 → 点「获取最新关注」→ 核对「x 分钟前关注」→ 勾选其负责设备 → 确定。之后该设备告警按 §5 模板消息发到其微信。

## 7. 使用须知

- 页面数据自动刷新，不用手动刷新浏览器；配置（阈值、接收人）保存后持久保留，重启浏览器不丢；
- 同一（设备, 指标, 类型）告警 **10 分钟内只报一次**（防刷屏），演示后想马上再触发就换指标或换设备；
- 告警记录最多 500 条，只增不减，可定期「清空记录」；
- 顶栏没有「检测器」指示 = 前端跑在模拟数据模式（内置模拟器，无需后端），演示链路与真实一致。

## 8. 参数与设备速查

| 指标 | 单位 | 默认阈值（下~上） | 正常区间 |
