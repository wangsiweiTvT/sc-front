# 前端操作说明书（九厂一期工艺参数监控大屏）

> 面向使用/演示这套监控大屏的人：每个页面有什么、怎么操作、各种标识什么意思。安装部署见 [windows-deploy.md](windows-deploy.md)，系统结构见 [system-guide.md](system-guide.md)。

## 1. 产品简介

本系统对 **4 台九厂一期工艺参数传感器**做 7×24 实时监控：每台设备每 13 分钟经 MQTT 上报 6 项水质参数（沉降速度、沉降比、机加池出水浊度、PH、温度、反应池污泥浓度），大屏实时展示设备状态与参数值，越限或离线时由后端检测器自动生成告警记录，并按订阅名单发送短信/微信通知。

界面共三个页面（顶栏菜单切换）：**实时监控 · 告警记录 · 阈值配置**。

## 2. 界面总览（顶栏）

| 元素 | 说明 |
|---|---|
| 九厂一期工艺参数监控 | 系统标题 |
| 实时监控 / 告警记录 / 阈值配置 | 三个页面入口，点击即切换 |
| ● 检测器运行中 / ● 检测器已停止 | 后端告警检测器心跳（绿=正常，红=已停止；每 60 秒刷新）。**模拟数据模式下不显示**——顶栏没有这一项说明前端跑在内置模拟器上 |
| 在线 n · 离线 n · 异常 n | 四台设备的状态实时统计，随监控页数据每约 2 秒刷新 |
| 右上时钟 | 当前时间（每秒跳） |
| 🔔 铃铛 | 未读告警数角标。点击 = 标记全部已读并跳转告警记录页 |

## 3. 实时监控页

### 3.1 页面布局与刷新

主界面为 2×2 四张设备卡片，每张对应一台设备。页面**约 2 秒自动刷新**一次，无需手动刷新浏览器。

### 3.2 设备卡片怎么读

一张卡片从上到下：

- **标题**：设备编号（如 `Di-Jiu-Shui-Chang-1`），是设备在系统中的唯一标识；
- **右上角状态角标**：在线（绿）/ 离线（灰）/ 异常（红），判定规则见 3.3；
- **中部 6 项参数当前值**：沉降速度 m/h、沉降比 %、机加池出水浊度 NTU、PH、温度 ℃、反应池污泥浓度 g/L。**越限的参数红色加粗**显示（严格超出才红，正好压在限值上不算）；
- **底部最近上报时间**：显示「日期 时间（n s 前）」，倒计时随刷新跳动——**超过 13 分钟无上报即判离线**。

### 3.3 状态角标判定规则（前端展示层计算）

| 状态 | 判定 |
|---|---|
| 离线 | 超过 13 分钟无新上报 |
| 异常 | 任一「参与监控」的参数当前值严格超出上下限（压线不算） |
| 在线 | 其余情况 |

> 角标只作展示提示，关闭浏览器角标即消失；**告警判定与短信/微信发送由后端检测器完成**，不受浏览器影响。

### 3.4 设备详情抽屉

**点击任意卡片**，右侧滑出该设备的详情抽屉：

1. 顶部为设备图片；
2. 档案信息表：设备编号、状态（与角标一致）、负责人、通信方式、最近上报时间；
3. 下方 6 个参数值方块——**点击任一方块**，底部切换显示该参数的**历史趋势曲线**（进入抽屉默认显示沉降比）；
4. 点抽屉外区域或右上角 × 关闭。

## 4. 告警记录页

### 4.1 记录从哪来、怎么刷新

告警由**后端检测器**生成（每 10 秒扫一次库判定，浏览器关着也会产生），本页**每 30 秒自动拉取**刷新。**新告警到达时**：页面右上方弹出通知（严重=红、警告=黄），顶栏铃铛角标 +1。

### 4.2 筛选记录

页面上方两个下拉框可**组合过滤**：

1. 按设备：选某台设备编号，只看它的告警；
2. 按类型：超上限 / 超下限 / 离线；
3. 两个条件可同时生效；下拉框右侧的 × 可单独清除该条件，恢复全部。

### 4.3 列字段含义

| 字段 | 含义 |
|---|---|
| 时间 | 告警发生时间（新记录在前） |
| 设备 / 参数 | 告警来源（设备以编号显示）；离线告警参数列显示「整机」 |
| 类型 | 超上限（黄）/ 超下限（黄）/ 离线（红） |
| 当前值 / 阈值 | 触发时的参数值与所越的限值 |
| 级别 | 警告（参数越限）/ 严重（离线） |
| 短信 | 已发送 / 发送中 / 失败，及接收人数；**名单为空时显示失败** |

### 4.4 页面操作

- **清空记录**（右上红钮）：点击 → 二次确认 → 删除全部告警记录。记录上限保留 500 条，超出自动丢最旧，可定期清理；
- **标记已读**：点顶栏铃铛即全量已读、角标清零（不影响记录本身）。

## 5. 阈值配置页

### 5.1 告警阈值

按设备分 4 个标签页（标签为设备编号），每页 6 行参数，可改**下限 / 上限 / 参与监控开关**：

1. 点击标签页切换到目标设备；
2. 直接在表格行内修改上下限数值，或用「参与监控」开关控制该参数是否参与判定；
3. 改完点右上**保存**——校验规则：下限必须小于上限，不满足会红字提示具体设备与参数；
4. 保存成功后的生效节奏：设备**状态角标立即**按新阈值展示；**后端告警判定约 10 秒内**采纳新阈值。

各参数默认阈值与正常区间见 §8 速查表。

### 5.2 短信/微信接收人（按设备订阅）

页面下方卡片管理告警通知名单。**每个接收人勾选自己负责的设备，只收这些设备的告警（越限 + 离线）**。表格列：姓名、手机号、订阅设备（4 个勾选框）、微信 openid（可直接看出谁已配置，未配置显示灰字）、操作。

**添加接收人**：

1. 点「添加接收人」打开弹窗；
2. 填姓名 + 手机号（须 1 开头 11 位）；
3. 勾选要订阅的设备（一个都不勾 = 收不到任何告警）；
4. 微信 openid 可选（不配则微信渠道无法送达，短信不受影响），配置方式见下；
5. 点「确定」即生效，新告警约 10 秒内按新名单发送。

**配置微信 openid（扫码获取）**：

1. 让这个人用微信**扫弹窗里的测试号二维码**关注测试号；
2. 关注后点二维码旁的「**获取最新关注**」按钮，系统拉取最新扫码者的 openid 填入（**仅输入框为空时填入**，已有值不覆盖，要换人先清空再获取）；
3. 核对绿字提示「x 分钟前关注」的时间对得上（确认拉到的确实是刚扫码的人，不是早前关注的别人）再提交；
4. 没有人扫码时点按钮会提示「暂无新关注」；获取失败（渠道未配置/接口异常）会弹错误提示。

**编辑**：每行「编辑」打开同一弹窗并回填全部字段；**清空 openid 保存即取消该人的微信渠道**（其余不变）。已绑定过接收人的关注者不会被「获取最新关注」返回。

**订阅设备**：表格内勾选框**勾选/取消即保存**（无需进编辑弹窗），约 10 秒被后端采纳；一个设备都不勾时该行提示「未订阅任何设备，将不会收到短信」。

**删除**：点「删除」→ 二次确认 → 移出名单。

> **上线前务必给每台设备配好订阅人**：某设备没有任何人订阅时，它的告警短信/微信状态记为「失败」、接收人为空。渠道开关在后端 `.env`（`SMS_PROVIDER=wechat_sandbox`），前端无需配置。

## 6. 常用操作场景

**场景 A —— 演示 / 验证越限告警**：

1. 阈值配置页选一台设备，把某参数上限调低到当前值以下（如沉降比上限改为 5）；
2. 保存后等约 10 秒：告警记录页出现「超上限 / 警告」记录，页面弹通知，短信列显示「已发送」（前提：该设备已有订阅接收人；后端 `SMS_PROVIDER=dryrun` 时短信只记日志）；
3. 演示完把阈值改回。

**场景 B —— 演示离线告警**：

让某设备停止上报（或停掉模拟发送端），13 分钟后产生「离线 / 严重」告警；设备恢复上报**不会**产生「恢复告警」。

**场景 C —— 日常巡检**：

打开大屏 → 看顶栏「检测器运行中」是否为绿、四台设备角标有无离线/异常 → 有未读铃铛则点开处理 → 必要时按设备/类型筛选查历史告警。

**场景 D —— 给值班人员配微信通知**：

阈值配置页 → 添加接收人 → 该人扫弹窗内二维码关注测试号 → 点「获取最新关注」→ 核对「x 分钟前关注」→ 勾选其负责的设备 → 确定。之后该设备的告警会以模板消息发到其微信。

## 7. 使用须知

- 页面数据自动刷新，无需手动刷新浏览器；配置（阈值、接收人）保存后持久保留，重启浏览器不丢；
- 同一（设备, 参数, 类型）的告警 **10 分钟内只报一次**（冷却防刷屏），演示后想立即再触发请换参数或换设备；
- 告警记录上限 500 条，只增不减，可定期「清空记录」；
- 顶栏无「检测器」指示 = 前端跑在模拟数据模式（内置模拟器，无需后端），演示链路与真实模式一致。
