# 前端操作说明书（九厂一期工艺参数监控大屏）

> 面向使用/演示这套监控大屏的人：每个页面有什么、怎么操作、各种标识什么意思。安装部署见 [windows-deploy.md](windows-deploy.md)，系统结构见 [system-guide.md](system-guide.md)。

## 1. 产品简介

本系统对 **4 台九厂一期工艺参数传感器**（沉淀池 3 台 + 加药间 1 台）做 7×24 实时监控：每台设备每 13 分钟经 MQTT 上报 6 项水质参数，大屏实时展示设备状态与参数值，越限或离线时由后端检测器自动生成告警记录并按名单发送短信通知。

界面共三个页面（顶栏菜单切换）：**实时监控 · 告警记录 · 阈值配置**。

## 2. 界面总览（顶栏）

| 元素 | 说明 |
|---|---|
| 九厂一期工艺参数监控 | 系统标题 |
| 实时监控 / 告警记录 / 阈值配置 | 三个页面入口 |
| ● 检测器运行中 / ● 检测器已停止 | 后端告警检测器心跳（绿=正常，红=已停止；每 60 秒刷新）。**模拟数据模式下不显示** |
| 在线 n · 离线 n · 异常 n | 四台设备的状态实时统计 |
| 右上时钟 | 当前时间（每秒跳） |
| 🔔 铃铛 | 未读告警数角标。点击 = 标记全部已读并跳转告警记录页 |

## 3. 实时监控页

主界面为 2×2 四张设备卡片，约 2 秒自动刷新一次。

**设备卡片**（一张 = 一台设备）：

- 标题：设备编号（如 `Di-Jiu-Shui-Chang-1`）；右上角为**状态角标**（在线 / 离线 / 异常）；
- 中部：6 项参数当前值（沉降速度 m/h、沉降比 %、机加池出水浊度 NTU、PH、温度 ℃、反应池污泥浓度 g/L）；**越限的参数红色加粗**显示；
- 底部：最近上报时间及「(n s 前)」倒计时——超过 13 分钟无上报即判离线。

**点击卡片**打开设备详情抽屉：

- 设备图片；
- 档案信息：设备编号、状态、负责人、通信方式、最近上报时间；
- 6 项参数当前值方块——**点击任一参数**，下方切换显示该参数的**历史趋势曲线**（默认显示沉降比）。

**状态角标判定规则**（前端展示层计算）：

| 状态 | 判定 |
|---|---|
| 离线 | 超过 13 分钟无新上报 |
| 异常 | 任一「参与监控」的参数当前值严格超出上下限（压线不算） |
| 在线 | 其余情况 |

> 角标只作展示，关闭浏览器角标即消失；告警判定与短信由后端检测器完成，不受浏览器影响。

## 4. 告警记录页

告警由**后端检测器**生成（浏览器关着也会产生），本页每 30 秒自动拉取刷新；新告警到达时右上方弹通知（按级别红/黄），铃铛角标 +1。

**筛选**：按设备、按类型（超上限 / 超下限 / 离线）组合过滤，可清除条件恢复全部。

**列表字段**：

| 字段 | 含义 |
|---|---|
| 时间 | 告警发生时间（新记录在前） |
| 设备 / 参数 | 告警来源（设备以编号显示，如 `Di-Jiu-Shui-Chang-1`）；离线告警参数列显示「整机」 |
| 类型 | 超上限（黄）/ 超下限（黄）/ 离线（红） |
| 当前值 / 阈值 | 触发时的参数值与所越的限值 |
| 级别 | 警告（参数越限）/ 严重（离线） |
| 短信 | 已发送 / 发送中 / 失败，及接收人数；名单为空时发送失败 |

**操作**：

- **清空记录**（右上红钮）：二次确认后删除全部告警（上限保留 500 条，超出自动丢最旧）；
- **标记已读**：点顶栏铃铛即全量已读、角标清零。

## 5. 阈值配置页

### 5.1 告警阈值

按设备分 4 个标签页（标签为设备编号，如 `Di-Jiu-Shui-Chang-1`），每页 6 行参数，可改**下限 / 上限 / 参与监控开关**：

1. 改完后点右上**保存**（校验：下限必须小于上限）；
2. 保存成功后：设备**状态角标立即**按新阈值展示；**后端告警判定约 10 秒内**采纳新阈值；
3. 「参与监控」关闭的参数不参与异常判定与告警。

### 5.2 短信接收人（按设备订阅）

页面下方卡片管理告警短信名单。**每个接收人勾选自己负责的设备，只收这些设备的告警短信**（越限 + 离线）：

- **添加接收人**：姓名 + 手机号（1 开头 11 位）+ 勾选订阅设备 + 微信 openid（可选），确定即生效；
- **编辑**：每行「编辑」打开同一弹窗并回填全部字段。**微信 openid** 是微信测试号渠道的送达标识——表单内嵌测试号**二维码**，扫码关注后点旁边的「**获取最新关注**」按钮即拉取最新扫码者的 openid 填入（仅输入框为空时填入，已有值不覆盖，要换人先清空再获取），并显示「x 分钟前关注」，确认时间对得上再提交；暂无新关注或获取失败会给出提示；已绑定过接收人的关注者不会被返回（管理员自己扫不会填自己），此时仍可在测试号用户列表手动复制 openid 填入；**清空即取消该渠道**。未配 openid 的接收人在微信渠道下发送判失败，不影响其他人，告警照常落库；渠道开关在后端 `.env`（`SMS_PROVIDER=wechat_sandbox`），前端无需配置；
- **订阅设备列**：表格内 4 个勾选框（显示设备编号），**勾选/取消即保存**，约 10 秒被后端检测器采纳；「微信 openid」列可直接看出谁已配置（未配置显示灰字）；
- **未订阅提示**：一个设备都不勾时，该行显示「未订阅任何设备，将不会收到短信」——不订阅 = 收不到任何短信（显式订阅才收，没有全员兜底）；
- **删除**：二次确认后移出名单；
- 某设备**没有任何人订阅**时，该设备的告警短信状态记为「失败」、接收人为空——**上线前务必给每台设备配好订阅人**。

## 6. 常用操作场景

**场景 A —— 演示 / 验证越限告警**：

1. 阈值配置页选一台设备，把某参数上限调低到当前值以下（如沉降比上限改为 5）；
2. 保存后等约 10 秒：告警记录页出现「超上限 / 警告」记录，页面弹通知，短信列显示「已发送」（前提：该设备已有订阅接收人；后端 `SMS_PROVIDER=dryrun` 时短信只记日志）；
3. 演示完把阈值改回。

**场景 B —— 演示离线告警**：

让某设备停止上报（或停掉模拟发送端），13 分钟后产生「离线 / 严重」告警；设备恢复上报**不会**产生「恢复告警」。

**场景 C —— 日常巡检**：

打开大屏 → 看顶栏「检测器运行中」是否为绿、四台设备角标有无离线/异常 → 有未读铃铛则点开处理 → 必要时按设备/类型筛选查历史告警。

## 7. 使用须知

- 页面数据自动刷新，无需手动刷新浏览器；配置（阈值、接收人）保存后持久保留，重启浏览器不丢；
- 同一（设备, 参数, 类型）的告警 **10 分钟内只报一次**（冷却防刷屏），演示后想立即再触发请换参数或换设备；
- 告警记录上限 500 条，只增不减，可定期「清空记录」；
- 顶栏无「检测器」指示 = 前端跑在模拟数据模式（内置模拟器，无需后端），演示链路与真实模式一致。
