# 前端操作说明书（九厂一期工艺参数监控大屏）

> 这本手册写给**第一次接触这套系统的人**：系统是干嘛的、每个页面怎么用、微信/短信里会收到什么。安装部署见 [windows-deploy.md](windows-deploy.md)，系统结构见 [system-guide.md](system-guide.md)。

## 0. 三分钟看懂这套系统

**这套系统是干嘛的？**

它像给 4 台水处理设备请了一个 **7×24 小时不休息的值班员**：每 13 分钟读一次每台设备的 6 个水质指标，数值一旦越界、或设备失联，就自动记一条告警，并按名单把通知发到值班人的**手机微信（或短信）**上。大屏就是那个值班员的「监控台」——电脑上打开浏览器就能看。

**几个必须知道的名词（大白话）**

| 名词 | 大白话解释 |
|---|---|
| 设备 | 被监控的 4 台水质传感器，每台有个**编号**当身份证，形如 `Di-Jiu-Shui-Chang-1` |
| 指标（参数） | 每台设备上报的 6 个水质数值：沉降速度、沉降比、机加池出水浊度、PH、温度、反应池污泥浓度 |
| 阈值 | 你给每个指标划的「安全线」——一个下限、一个上限。数值跑到线外 = 异常 |
| 越限 | 数值超上限或低于下限（压线不算，要**严格**超出） |
| 离线 | 设备超过 13 分钟没上报数据（可能断电、断网、坏了） |
| 告警 | 越限或离线时系统记下的一条记录，同时发通知 |
| 接收人 | 出事时通知谁——存的是**手机号**，可额外配**微信** |
| 检测器 | 后端那个「巡逻员」程序，每 10 秒检查一次数据，负责判定告警和发通知 |

> **一个会混淆的点提前说清**：大屏界面上设备一律显示**编号**（`Di-Jiu-Shui-Chang-1`），而**微信/短信通知里显示中文名**（`九厂一期-1#`）——它们是同一台设备，对照表见 §9。

## 1. 产品简介

系统监控 4 台九厂一期工艺参数传感器（3 台沉淀池 + 1 台加药间），每台每 13 分钟经 MQTT 上报 6 项水质参数，大屏实时展示设备状态与参数值，越限或离线时由后端检测器自动生成告警记录并按名单发送通知。

界面共三个页面（顶栏菜单切换）：**实时监控 · 告警记录 · 阈值配置**。

## 2. 界面总览（顶栏）

顶栏一行是全局信息，任何页面都看得到：

| 元素 | 是什么、怎么用 |
|---|---|
| 九厂一期工艺参数监控 | 系统标题 |
| 实时监控 / 告警记录 / 阈值配置 | 三个页面入口，点哪个就去哪个页面 |
| ● 检测器运行中 / ● 检测器已停止 | 后端检测器的心跳：绿=正常在岗，红=已停。每 60 秒刷新一次。**如果顶栏没有这一项**，说明前端跑在模拟数据模式（内置模拟器，不连后端） |
| 在线 n · 离线 n · 异常 n | 四台设备的状态统计，随数据每约 2 秒刷新 |
| 右上时钟 | 当前时间 |
| 🔔 铃铛 | 未读告警数角标。点一下 = 全部标记已读并跳到告警记录页 |

## 3. 实时监控页

**这页干嘛的：** 一屏看全 4 台设备的实时状态，谁出问题一眼就知道。

### 3.1 布局与刷新

主界面是 2×2 四张设备卡片，每张一台设备。页面**约 2 秒自动刷新**一次，你什么都不用做，数据自己会跳。

### 3.2 卡片怎么看

一张卡片从上到下：

- **标题**：设备编号（`Di-Jiu-Shui-Chang-1`）；
- **右上角状态角标**：在线（绿）/ 离线（灰）/ 异常（红）；
- **中部 6 个指标当前值**：沉降速度、沉降比、机加池出水浊度、PH、温度、反应池污泥浓度。**越限的那一项会变红色加粗**，一眼锁定是哪个指标出问题；
- **底部最近上报时间**：`日期 时间（n 秒前）`，倒计时一直走——**超过 13 分钟没新数据就判离线**。

### 3.3 状态角标怎么判定

| 状态 | 判定规则 |
|---|---|
| 离线 | 超过 13 分钟无新上报 |
| 异常 | 任一「参与监控」的指标当前值**严格**超出上下限（压线不算） |
| 在线 | 其他情况 |

> 角标只是**展示提示**（关掉浏览器就没了）；真正的告警判定和发通知由后端检测器干，浏览器关着也照常进行。

### 3.4 设备详情抽屉

**点任意卡片**，右侧滑出该设备的详情：

1. 顶部是设备照片；
2. 档案信息：设备编号、状态、负责人、通信方式、最近上报时间；
3. 下面 6 个指标值方块——**点任一方块**，底部切换成该指标的**历史趋势曲线**（进来默认显示沉降比）；
4. 点抽屉外或右上 × 关闭。

## 4. 告警记录页

**这页干嘛的：** 看历史告警——谁、什么时候、哪个指标出了问题。

### 4.1 记录从哪来、怎么刷新

告警由**后端检测器**生成（每 10 秒扫一次库，浏览器关着也会产生），本页**每 30 秒自动拉取**刷新。**新告警到达时**：右上弹通知（严重=红、警告=黄），铃铛角标 +1。

### 4.2 怎么筛选

页面上方两个下拉框可**组合过滤**：

1. 按设备：只挑某台设备的告警；
2. 按类型：超上限 / 超下限 / 离线；
3. 两个可同时生效；下拉框右侧 × 可单独清掉该条件，恢复全部。

### 4.3 每一列什么意思

| 字段 | 含义 |
|---|---|
| 时间 | 告警发生时间（新记录排最前） |
| 设备 / 参数 | 哪台设备的哪个指标（设备以编号显示）；离线告警参数列显示「整机」 |
| 类型 | 超上限（黄）/ 超下限（黄）/ 离线（红） |
| 当前值 / 阈值 | 触发时的数值、和它越过的那条线 |
| 级别 | 警告（指标越限）/ 严重（离线） |
| 短信 | 已发送 / 发送中 / 失败，及接收人数；**名单为空时显示失败** |

### 4.4 页面操作

- **清空记录**（右上红钮）：点 → 再确认一次 → 删光全部告警。记录最多留 500 条，满了自动丢最旧的；
- **标记已读**：点顶栏铃铛，角标清零（记录本身不动）。

## 5. 阈值配置页

**这页干嘛的：** 定「安全线」（阈值）和「通知谁」（接收人）——这是日常最常改的地方。

### 5.1 告警阈值

按设备分 4 个标签页（标签是设备编号），每页 6 个指标，每个指标可改**下限 / 上限 / 参与监控开关**：

1. 点标签页切到要改的设备；
2. 直接在表里改上下限数值；「参与监控」开关关掉 = 这个指标出问题**不报警**；
3. 改完点右上**保存**——校验规则：下限必须小于上限，写反了会红字告诉你哪台设备哪个指标错了；
4. 保存后的生效节奏：**界面角标立即**按新线变，**后端判定约 10 秒内**采纳。

各指标默认安全线见 §9。

### 5.2 接收人（按设备订阅）

页面下方卡片管「通知名单」。**每个接收人勾自己负责的设备，只收这些设备的告警**。表格列：姓名、手机号、订阅设备（4 个勾选框）、微信 openid、操作。

**添加接收人**：

1. 点「添加接收人」；
2. 填姓名 + 手机号（1 开头的 11 位）；
3. 勾选要订阅的设备（一个都不勾 = 收不到任何告警）；
4. 微信 openid 可选（不配则微信发不了，短信照常），配法见下；
5. 点「确定」生效，新告警约 10 秒内按新名单发送。

**配微信 openid（扫码获取）**：

1. 让这个人用微信**扫弹窗里的测试号二维码**关注测试号；
2. 关注后点旁边的「**获取最新关注**」按钮，系统拉最新扫码者的 openid 填进输入框（**仅输入框为空时填**，已有值不覆盖，要换人先清空再点）；
3. 核对绿字「x 分钟前关注」的时间对得上（确认拉到的真是刚扫码这个人，不是早前关注的别人）再提交；
4. 没人扫码时点按钮提示「暂无新关注」；获取失败（渠道没配 / 微信接口异常）会弹错误提示。

**编辑**：每行「编辑」打开同一弹窗并回填全部字段；**清空 openid 保存 = 取消这个人的微信通知**（其他不变）。已绑定过接收人的关注者不会被「获取最新关注」返回。

**订阅设备**：表格里勾选框**勾上/取消立刻保存**（不用进编辑弹窗），约 10 秒被后端采纳；一个都不勾时该行提示「未订阅任何设备，将不会收到短信」。

**删除**：点「删除」→ 再确认 → 移出名单。

> **上线前务必给每台设备配好订阅人**：某设备没人订阅时，它的告警通知状态记「失败」、接收人为空。微信渠道开关在后端 `.env`（`SMS_PROVIDER=wechat_sandbox`），前端不用管。

## 6. 微信会收到什么

告警一旦触发，订阅了该设备且配了 openid 的人，手机会收到一条**公众号模板消息**（像公众号推送一样，有提醒）。消息固定四行「标签 + 值」：

| 行标签 | 填什么 |
|---|---|
| 设备 | 设备中文名（如 `九厂一期-1#`） |
| 内容 | 「指标名 数值+单位」；离线时为「设备离线」 |
| 详情 | 「超上限 / 低于下限 + 阈值+单位」；离线时为「超过 N 分钟」 |
| 时间 | 告警时间，`月-日 时:分:秒` |

**收到后的样子（真实样例）**

① 指标越限（例：沉降比飙到 36.2，超了上限 35）：

```
设备：九厂一期-1#
内容：沉降比 36.2%
详情：超上限 35%
时间：10-20 21:15:48
```

② 设备离线（例：九厂一期-1# 失联）：

```
设备：九厂一期-1#
内容：设备离线
详情：超过13分钟
时间：10-20 21:15:48
```

> 每个值最多显示 16 个字，超长会截断加「…」；文字统一深蓝色。**注意**：消息里的「九厂一期-1#」就是大屏上的「Di-Jiu-Shui-Chang-1」，同一台设备（对照见 §9）。

## 7. 常用操作场景

**场景 A —— 演示「指标越限报警」**：

1. 阈值配置页选一台设备，把某指标上限调低到当前值以下（如沉降比上限改成 5）；
2. 保存后等约 10 秒：告警记录页出现「超上限 / 警告」记录，页面弹通知，短信列显示「已发送」（前提：该设备已配订阅人；后端 `SMS_PROVIDER=dryrun` 时只记日志、不真发）；
3. 演示完把阈值改回来。

**场景 B —— 演示「离线报警」**：

让某台设备停止上报（或停掉模拟发送端），13 分钟后产生「离线 / 严重」告警；设备恢复上报**不会**产生「恢复告警」。

**场景 C —— 日常巡检**：

打开大屏 → 看顶栏「检测器运行中」是否绿、四台设备角标有无离线/异常 → 有未读铃铛点开处理 → 必要时按设备/类型筛选查历史告警。

**场景 D —— 给值班人员配微信通知**：

阈值配置页 → 添加接收人 → 该人扫弹窗内二维码关注测试号 → 点「获取最新关注」→ 核对「x 分钟前关注」→ 勾选其负责的设备 → 确定。之后该设备的告警会以 §6 的模板消息发到其微信。

## 8. 使用须知

- 页面数据自动刷新，不用手动刷新浏览器；配置（阈值、接收人）保存后持久保留，重启浏览器不丢；
- 同一（设备, 指标, 类型）的告警 **10 分钟内只报一次**（防刷屏），演示后想马上再触发就换指标或换设备；
- 告警记录最多 500 条，只增不减，可定期「清空记录」；
- 顶栏没有「检测器」指示 = 前端跑在模拟数据模式（内置模拟器，无需后端），演示链路与真实一致。
