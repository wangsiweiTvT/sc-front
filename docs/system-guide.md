# 系统结构说明（九厂一期工艺参数监控）

> 面向初次接手的人：这套系统由哪几块组成、数据怎么流、每个配置项什么意思。操作步骤（装、启、停、排障）见 [windows-deploy.md](windows-deploy.md)。

## 1. 一句话

4 台九厂一期工艺参数传感器 → MQTT → 后端入库并由**常驻检测器**自动判定告警/发短信 → 浏览器大屏实时展示与配置。

## 2. 组件与数据流

```
4 台传感器设备（Di-Jiu-Shui-Chang-1..4）
每 13 分钟上报一次 6 参数：Sf 沉降速度 / Vf 沉降比 / Fc 流量 / pHf pH / Tf 温度 / Cf 余氯
        │  MQTT 主题 Chen-Su-Yi/<client_id>
        ▼
   MQTT Broker（:1883）
        │
        ▼
sc-backend · app.mqtt_consumer 采集端（订阅→解析→入库，重复投递幂等去重）
        │ 写入
        ▼
   MySQL · mqtt_data 库 ◄──────────────────────┐
   ├ sensor_data   原始读数                     │ 读/写
   ├ alarms        告警记录（检测器生成）         │
   ├ thresholds    阈值规则（前端可改，检测器读）  │
   ├ receivers     短信接收人                    │
   └ detector_status 检测器心跳                  │
        ▲                                       │
        │ 每 10 秒扫库：越限/离线 → 告警入 alarms  │
sc-backend · app.anomaly_detector 检测器 ───────┘
        │ 同时按 receivers 名单发短信（dryrun 只记日志 / aliyun 真发）
        ▼
sc-backend · app.api REST API（:8000，读全部表供前端）
        ▲
        │ HTTP 轮询：快照 2s · 告警 30s
sc-front 浏览器大屏（Vue3）
```

## 3. 各组件职责

| 组件 | 技术 | 职责 | 不做什么 |
|---|---|---|---|
| sc-front | Vue3 + TS + Element Plus | 实时展示状态角标与参数值、告警列表/通知/未读数、阈值与接收人配置 | **不判定告警、不发短信**（二期已移交后端） |
| app.mqtt_consumer | paho-mqtt | 订阅 `Chen-Su-Yi/#`，解析入库；同一设备+同一上报时间只存一条 | 不判定、不供 HTTP |
| app.anomaly_detector | 常驻进程 | 每 10 秒扫库：启用参数越限（严格 `>` 上限 / `<` 下限，压线不算）、离线（超 780 秒无上报）→ 生成告警；同（设备,参数,类型）10 分钟冷却；按名单发短信 | 不提供 HTTP |
| app.api | FastAPI | REST：最新快照 / 历史 / 告警（读+删，上限 500 条）/ 阈值 / 接收人 / 检测器心跳 | 不判定 |
| app.mqtt_client | 模拟器 | 无真实设备时模拟 4 台设备定时上报（仅演示/测试用） | 生产环境不需要 |
| MySQL | 8.x | 唯一数据落点 | — |

## 5. 配置参考

### 后端 `.env`（后端仓库根目录，从 `.env.example` 复制，git 忽略）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DB_PASSWORD` | （必填） | MySQL 密码，缺失时服务拒绝启动 |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | 数据库地址 |
| `DB_USER` / `DB_NAME` | `root` / `mqtt_data` | 账号 / 库名 |
| `SMS_PROVIDER` | `dryrun` | `dryrun` 只记日志不发；`aliyun` 真发（另需 `SMS_ALIYUN_*` 四项） |
| `DETECTOR_POLL_SECONDS` | `10` | 检测器扫描周期 |
| `DETECTOR_OFFLINE_SECONDS` | `780` | 离线判定窗口（= 13 分钟，与上报周期一致） |

> MQTT broker 地址目前是代码常量（`app/mqtt_consumer.py` 的 `BROKER_HOST`、`app/mqtt_client.py` 的 `MQTT_BROKER_HOST`，默认 `127.0.0.1`），不是环境变量。

### 前端 `.env.local`（前端仓库根目录，git 忽略）

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITE_USE_MOCK` | `true` | `true`/缺省 = 模拟数据（内置模拟器，不需要后端）；`false` = 真实后端 |
| `VITE_API_BASE` | `http://127.0.0.1:8000` | 后端 API 地址，**以浏览器所在机器的视角**填写 |

生效规则：dev 模式改完**重启 dev server**；build 会把值打进产物，改完必须**重新 build**。

## 6. 告警链路（谁在什么时候做什么）

1. 检测器每 10 秒扫一次 `sensor_data`；
2. 判定：启用参数越限 → `warning` 级告警；超 780 秒无上报 → `critical` 级离线告警（设备恢复不产生「恢复告警」）；
3. 同（设备,参数,类型）10 分钟内只报一次（冷却防刷屏）；
4. 告警写入 `alarms`（上限 500 条，前端可整表清空）；
5. 短信按 `receivers` 名单发送，状态（`sent` / `failed`）随告警记录可查；
6. 前端每 30 秒拉一次告警列表：新记录弹桌面通知、计入未读（已读水位之后的新增数）；
7. 阈值 / 接收人改动约 10 秒后生效（检测器下个扫描周期重读配置）。

**状态角标 vs 告警记录（易混点）：**

- 角标（在线/离线/异常）：前端每 2 秒拉快照后**自行计算，仅作展示**，关掉浏览器角标就没了——但不影响任何告警；
- 告警记录 + 短信：**后端检测器**生成，7×24 常驻，浏览器关着照常判定和发送。

## 7. 关键常量速查

| 数值 | 含义 |
|---|---|
| 13 分钟 | 设备上报周期 = 离线判定窗口（780 秒） |
| 10 秒 | 检测器扫描周期 / 配置（阈值、接收人）采纳延迟 |
| 30 秒 | 前端告警列表轮询周期 |
| 2 秒 | 前端快照刷新周期 |
| 10 分钟 | 同类告警冷却 |
| 500 条 | 告警记录上限 |

## 8. 概念 FAQ

- **浏览器关了短信还在发？** 对，判定和发送都在后端检测器进程里，与浏览器无关。
- **改了阈值为什么要等约 10 秒？** 检测器按扫描周期重读 `thresholds` 表，不是即时推送。
- **mock 模式是什么？** 前端内置了一套模拟器（含与后端同语义的模拟检测器），不启后端也能完整演示告警链路；顶栏**没有**「检测器运行中」指示即 mock 模式。
- **怎么演示一条告警？** 设置页调低某参数上限 → 约 10 秒内告警页出现 warning 记录、`sms.status` 变 `sent`；离线告警则让设备停止上报 13 分钟（或停掉模拟发送端）。
